3. KEPUTUSAN PENGGUNA (WAJIB DIPATUHI)
-------------------------------------------------------------------------------------
3.1 Instrumen & timeframe: XAUUSD.vx, timeframe M1 (tujuan scalping). M5 hanya boleh untuk
    riset/backtest, bukan eksekusi, kecuali pengguna menyetujui.
3.2 Lot tetap (default 0.01), diatur lewat LOT_SIZE di .env. Bukan dihitung dari persen risiko.
    (Boleh disediakan opsi LOT_MODE=risk_percent, default tetap "fixed".)
3.3 Hanya SATU posisi terbuka sekali waktu. Tidak boleh full margin, tidak boleh martingale,
    tidak boleh menggandakan lot, tidak boleh averaging.
3.4 Tidak ada take profit tetap. Trailing bertingkat dalam satuan R (R = jarak entry ke SL awal):
      - SL awal = SL(rugi), berjarak 1R.
      - Saat profit berjalan mencapai 1,5R, SL pindah ke +1R  -> SL(profit1).
      - Tiap tambahan 1R (2,5R, 3,5R, ...), SL naik jadi +2R, +3R, ...  -> SL(profit2), (profit3)...
      - SL TIDAK PERNAH mundur. Posisi tutup hanya saat harga menyentuh SL.
      - Rumus level: n = floor(profit_R - (first_trigger_r - 1)), dengan first_trigger_r = 1,5.
    Tiap transaksi dicatat label keluarnya: "SL rugi" atau "SL profitN".
3.5 Penghentian otomatis: setelah 3 kali "SL rugi" BERTURUT-TURUT (kena SL awal, belum pernah
    digeser), bot berhenti trading. "SL profitN" me-reset hitungan ke 0.
    - Setelah berhenti, bot lanjut otomatis di hari berikutnya (hitungan di-reset,
      pergantian hari jam 00.00 WIB).
    - Jika program dijalankan ulang di hari yang sama saat sedang terkunci: tampilkan alert
      dan menu: [1] Stop (tetap terkunci)  [2] Tetap lanjut (override). Override wajib
      konfirmasi mengetik kata LANJUT, direset ke 0 (jatah 3 lagi), dicatat di log, dan dikirim
      sebagai alert Gmail.
    - Pengguna menganggap batas rugi harian dan batas drawdown total tidak perlu. Sediakan
      sebagai OPSI di .env (MAX_DAILY_LOSS_PERCENT, MAX_DRAWDOWN_PERCENT), DEFAULT MATI.
3.6 Bot berjalan sepenuhnya otomatis tanpa pengawasan HP. Karena itu wajib ada: state yang
    bertahan saat bot mati, reconnect otomatis, log forensik, alert Gmail, dan SL SELALU
    terpasang di server pada setiap order (SL server-side melindungi posisi saat bot/laptop mati).
3.7 Posisi yang sedang terbuka saat bot dijalankan ulang harus dikenali dan dilanjutkan
    pengelolaannya (trailing), bukan diabaikan.
3.8 Alur script yang diinginkan pengguna:
      jalankan -> welcome/alert (+ data terakhir) -> pilih Start/Keluar ->
      cari signal (belum entry) -> entry buy/sell di harga saat ini -> proses (profit berjalan,
      label SL aktif) -> hasil (harga awal -> harga akhir, untung/rugi, label SL) ->
      ulangi cari signal; setelah 3 SL rugi tampil pesan STOP.
    Dashboard memakai library rich. Tampilkan hitungan "SL rugi beruntun: n/3".
3.9 Alert lewat Gmail (SMTP + App Password di .env). Kirim hanya kejadian penting:
    bot mulai/berhenti, terkunci 3 SL rugi, override, error/terputus/reconnect, ringkasan
    harian. Per transaksi cukup di dashboard dan trades.csv (opsional lewat flag).
3.10 AI (9router, endpoint OpenAI-compatible di localhost:20128/v1, model "prioritas") hanya
    meringkas berita ekonomi US hari ini (dari sumber kalender yang divalidasi). Jika AI/9router
    gagal, bot tetap jalan normal. AI tidak boleh memengaruhi entry/exit.
3.11 Target pengguna: win rate minimal 40%. CATATAN agent: dengan struktur payoff kita,
    win rate impas sekitar 38-40%, jadi 40% ~ impas. Ukuran keberhasilan yang benar adalah
    rata-rata R > 0, profit factor > 1, dan drawdown wajar setelah spread. Jangan mengejar win
    rate dengan cara yang merusak payoff (mis. menggeser SL ke untung terlalu dini).
3.12 Ide pengguna untuk riset (BUKAN fitur wajib, lihat Tahap 6): (1) analisis pola candlestick
    ala ICT sebagai validasi tambahan; (2) mode agresif "lihat candle berjalan ~10 detik lalu
    entry" -> hanya sebagai MODE BAYANGAN (merekam tanpa order) dulu.

      Tes gagal = tugas belum selesai. Jangan mematikan/menghapus tes demi lulus; perbaiki penyebabnya.

8. ATURAN KEJUJURAN ILMIAH (BACKTEST DAN RISET)
-------------------------------------------------------------------------------------
8.1 Tetapkan daftar uji dan kriteria lulus SEBELUM melihat hasil. Catat di docs/ (pra-registrasi).
8.2 Pisahkan data: pemilihan parameter hanya di bagian awal/pengembangan; ujian di data yang

8.3 Waspadai uji berganda: makin banyak kombinasi, makin besar peluang "menang kebetulan".

8.5 Pertahankan asumsi konservatif backtest (spread nyata dari data, entry di candle berikutnya,
    pergerakan merugikan lebih dulu, gap menembus SL). Jangan melonggarkannya demi hasil bagus.
8.6 Simpan SEMUA hasil, termasuk yang jelek, di docs/results/. Jangan menghapus hasil negatif.
8.7 Forward test (akun demo) adalah ujian bersih. Siapkan skrip analisis forward-test yang
    membandingkan hasil live-demo dengan backtest (frekuensi sinyal, slippage, spread, hasil).
    Jelaskan bahwa ~2 transaksi/hari berarti sebulan hanya ~50 transaksi: cukup untuk
    membuktikan MEKANISME dan biaya nyata, tidak cukup untuk membuktikan keunggulan kecil.
8.8 Jika bukti tidak mendukung keunggulan strategi, katakan itu terang-terangan di laporan akhir
    dan fokuskan klaim proyek pada kerangka uji yang disiplin, manajemen risiko, dan keandalan.


9. PERANGKAP TEKNIS MT5 DAN WINDOWS (PENGALAMAN NYATA DI PROYEK INI)
-------------------------------------------------------------------------------------
- copy_rates_from_pos dengan jumlah besar bisa gagal "(-2, Invalid params)": gunakan fallback
  jumlah lebih kecil (sudah ada di fetch_data.py). Set "Max bars in chart" ke Unlimited di MT5.
- Candle terakhir dari MT5 masih berjalan: buang/abaikan untuk sinyal (pakai candle tutup).
- Harga candle MT5 adalah BID. Ask = bid + spread. Buy masuk di ask, SL buy diuji pada bid.
  Sell masuk di bid, SL sell diuji pada ask.
- Spread di data adalah dalam POIN (bukan dolar): dolar = poin x point (0.01 untuk emas).
- Nama server berbeda antara tampilan portal broker dan MT5; pakai persis yang di MT5.
- Pesan "pasar ditutup"/tick kosong saat simbol baru diaktifkan: tunggu tick pertama sebelum
  menyimpulkan.
- Sebelum order: cek terminal_info().trade_allowed (Algo Trading aktif), account_info().trade_allowed,
  symbol_info().trade_mode, jarak SL >= trade_stops_level (dan freeze level), lot sesuai
  volume_min/step/max, mode pengisian (filling mode) yang didukung simbol, harga dinormalisasi
  ke digits. Gunakan konstanta mt5.TRADE_RETCODE_* (jangan hardcode angka) untuk menangani
  hasil: DONE, REQUOTE, REJECT, INVALID_STOPS, INVALID_FILL, MARKET_CLOSED, NO_MONEY,
  TRADE_DISABLED, CLIENT_DISABLES_AT, dst. Tangani tiap kasus dengan keputusan eksplisit
  (coba ulang terbatas, lewati, alert, atau berhenti).
- Mengubah SL posisi: TRADE_ACTION_SLTP dengan position ticket. Mengenali hasil posisi tertutup:
  history_deals_get berdasarkan position id (cek deal keluar, harga, profit, komisi, swap).
- Akun HEDGING: banyak posisi per simbol diizinkan oleh broker, tetapi bot kita tetap 1 posisi.
  Identifikasi posisi bot lewat magic number.
- Waktu: MT5 memberi waktu server (bukan UTC). Konversi eksplisit dan uji.
- Python 3.14 + pandas 3.x: hindari praktik chained assignment dan API yang usang.
- Smart App Control memblokir DLL pandas sebelumnya (sudah dimatikan pengguna). Jika kembali
  muncul "Application Control policy has blocked this file", jelaskan opsi ke pengguna
  (pindah ke Python 3.11, atau ekspor CSV manual), jangan memaksa.
- Unduhan file dari chat kadang gagal di sisi pengguna; selalu simpan hasil kerja langsung di
  repositori lokal, bukan sebagai lampiran.


10. RENCANA TAHAP (KERJAKAN BERURUTAN; TIAP TAHAP PUNYA KRITERIA SELESAI)
-------------------------------------------------------------------------------------

TAHAP 3 - FONDASI KEANDALAN (state, risiko, trailing, log)
  Tugas:
  a. bot/trailing.py: fungsi murni untuk level SL bertingkat (n = floor(profit_R - lock_gap)),
     hitung SL baru, tidak pernah mundur. Refaktor backtest/engine.py agar memakai fungsi yang SAMA.
  b. bot/risk.py: kelas pengunci (LossLock) murni: hitung SL(rugi) berturut-turut, kunci sampai
     pergantian hari WIB, override dengan reset, filter spread, filter jam (opsional, default mati),
     opsi batas rugi harian/drawdown (default mati). Dipakai bersama oleh engine dan bot live.
  c. bot/state.py: simpan/baca data\state.json secara atomik (tulis file sementara lalu ganti),
     tahan terhadap file rusak (cadangkan, mulai bersih, beri alert). Isi: hitungan SL rugi,
     hari terkunci, override, posisi terbuka (ticket, side, entry, sl_awal, r, level), transaksi
     terakhir, waktu aktif terakhir.
  d. bot/logger.py: logging dengan RotatingFileHandler ke logs\bot.log (format terstruktur,
     tanpa rahasia), plus logs\trades.csv (satu baris per transaksi: waktu masuk/keluar, arah,
     harga masuk/keluar, label SL, level, R, USD, spread, slippage).
  e. Konfigurasi strategi lewat .env/config (ATR_MULT, ADX_MIN, EMA, RSI, dst), default =
     kandidat (ATR 4, ADX 30) dengan peringatan "belum terbukti". Validasi di config.py.
  f. Tes: trailing (termasuk tidak pernah mundur), LossLock (3 rugi, reset oleh untung, pergantian
     hari, override), state (atomik, rusak), paritas engine-vs-modul bersama.
  Selesai jika: semua tes baru lulus; engine memakai modul bersama dan hasil backtest lama
  tidak berubah (bandingkan angka sebelum/sesudah pada data yang sama); log dan state
  terbentuk saat program dijalankan.

TAHAP 4 - EKSEKUSI LIVE DI AKUN DEMO
  Tugas:
  a. bot/mt5_client.py: tambah fungsi order (kirim order pasar dengan SL, ubah SL, tutup posisi
     darurat, baca posisi terbuka berdasarkan magic, baca riwayat deal), validasi pra-order
     (bagian 9), penanganan retcode, normalisasi harga/lot.
  b. bot/engine_live.py (atau serupa): loop utama sesuai alur 3.8:
       - deteksi candle M1 baru tutup -> hitung sinyal dari candle tutup -> filter (spread,
         terkunci, jam, satu posisi) -> entry buy/sell di harga saat ini dengan SL(rugi) = 1R
         (R dari ATR x mult saat sinyal) -> pantau posisi tiap 1-2 detik -> geser SL sesuai
         trailing -> deteksi posisi tertutup -> catat hasil (harga awal -> akhir, untung/rugi,
         label) -> perbarui hitungan/pengunci -> ulangi.
       - Saat start: rekonsiliasi posisi terbuka (adopsi posisi dengan magic bot, hitung level
         trailing dari SL yang ada), baca state.json, tampilkan data terakhir, tampilkan
         alert dan menu bila terkunci (3.5).
  c. Mode operasi di .env: MODE=signal_only (tampilkan sinyal, tanpa order; DEFAULT),
     MODE=demo_orders (kirim order, hanya akun demo). Pengguna yang mengganti mode, bukan agent.
  d. Ketahanan: reconnect dengan exponential backoff + alert, penanganan MT5 terputus di tengah
     posisi (jangan membuka posisi baru sampai rekonsiliasi selesai), penutupan rapi (Ctrl+C),
     tangkap semua exception di loop utama (log + alert, jangan crash diam-diam), watchdog
     detak jantung di log.
  e. Dashboard: status bot, harga, spread, indikator, alasan belum ada sinyal, posisi berjalan
     (profit USD dan R, label SL aktif), hitungan "SL rugi beruntun n/3", hasil terakhir, status
     kunci. Layar welcome menampilkan jenis akun (DEMO/REAL) mencolok.
  f. tools/smoke_order_test.py: uji end-to-end terkontrol di demo (buka 0.01 lot dengan SL,
     geser SL, tutup, verifikasi riwayat), butuh --yes-demo, menolak akun non-demo.
  g. Tes: fake MT5 (tiruan) untuk seluruh jalur order, retcode, reconnect, rekonsiliasi,
     pengelolaan trailing live berbanding data skenario; tes bahwa mode REAL ditolak.
  Selesai jika: semua tes lulus; smoke test demo berhasil (bukti log + riwayat MT5); bot
  signal_only berjalan stabil >= beberapa jam tanpa error di log; simulasi pemutusan koneksi
  pulih otomatis; bot dimatikan dan dinyalakan di tengah posisi demo melanjutkan trailing.

TAHAP 5 - ALERT DAN INFORMASI BERITA

  c. Ringkasan AI: kirim daftar berita ke 9router (POST /v1/chat/completions, Bearer key dari .env,

  Tugas:
